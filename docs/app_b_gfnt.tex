\section{GFNT 自訂點陣字型}
\label{app:gfnt}

\subsection{設計目的與產生方式}

GFNT 的目的是在不引入字型解析函式庫的前提下，讓程式能夠顯示中文。FreeGLUT 內建字型只支援 ASCII，而一般的 TTF 字型以曲線描述字形，必須先解析再光柵化，對這次作業而言過於複雜。

因此本專案事先將字型中的字形轉為點陣資料，並以簡單的二進位格式保存。程式執行時只需依 Unicode code point 找到對應的字形，取得其尺寸與定位資訊，再把點陣資料畫到畫面上。

目前隨程式附上兩套字型，使用者可在選單中切換，授權條款隨字型檔一同附上：
\begin{itemize}
    \item \textbf{Cubic 11（俐方體 11 號）}：以 12 px 轉換，共 10{,}268 個字元，風格為像素字型。
    \item \textbf{GNU Unifont}：以 16 px 轉換，共 57{,}071 個字元，涵蓋的字元範圍較廣。
\end{itemize}

\subsection{檔案結構}
\label{app:gfnt-layout}

GFNT 由三個區段依序組成，所有整數皆為 little-endian，各欄位的位置與大小如圖~\ref{fig:gfnt-layout}：
\begin{itemize}
    \item \textbf{Header}（16 bytes）：magic 固定為 \texttt{GFNT}，version 為 1；pixelSize 為轉換時的像素大小；ascender 與 descender 分別為基線上方與下方的高度；glyphCount 為字形數量 $N$。
    \item \textbf{Glyph Table}（$18N$ bytes）：每筆記錄一個字元的 code point、bitmap 寬高、bearing、advance，以及 bitmap 在 Bitmap Data 中的位移，並依 code point 嚴格遞增排列。
    \item \textbf{Bitmap Data}：所有字形的 bitmap 依序相接，每個像素以 1 byte 表示 alpha（0--255），列由上往下存放。
\end{itemize}
由於 Bitmap Data 緊接在 Glyph Table 之後，起點必為 $16+18N$，檔案不需要另外記錄各區段的位移。

\subsection{Font Metrics 與字形定位}
\label{app:gfnt-metrics}

字形以基線對齊。設文字區塊左上角的 Y 座標為 $y_0$，則第一行的基線為 $y_b=y_0+\text{ascender}$，每行的行高為 $\text{ascender}+\text{descender}$。對 pen 位置 $x_p$ 上的一個字形，其 bitmap 左上角為
\[
    x=x_p+\text{bearingX},\qquad y=y_b-\text{bearingY},
\]
畫完後 pen 前進 advanceX。bearingY 是 bitmap 頂端到基線的距離，因此 bitmap 高度大於 bearingY 的部分會延伸到基線以下，如圖~\ref{fig:gfnt-metrics} 中「你」的底部。由於每個字形只儲存實際有墨跡的範圍，空白字元的 bitmap 大小可以是 0，只用 advanceX 推進 pen。

\subsection{載入與驗證}
\label{app:gfnt-loader}

Loader 不直接把檔案內容複製進 C++ struct，而是逐欄位讀取 bytes 並以位移運算組合數值。這樣結果不受執行平台的 endian 與 struct padding 影響，負數也以明確的 two's complement 運算還原。

字型檔在載入時一次完成以下檢查，任何一項失敗都會拒絕載入：
\begin{itemize}
    \item 檔案至少包含完整的 Header，magic 與 version 正確，pixelSize 不為 0，ascender 與 descender 不為負數。
    \item glyphCount 所需的 Glyph Table 沒有超出檔案大小，避免依錯誤的數量配置記憶體。
    \item Glyph Table 依 code point 嚴格遞增，且每個 code point 都是合法的 Unicode 字元（不超過 U+10FFFF，也不是 surrogate）。
    \item 每個字形的 bitmap 範圍都位於 Bitmap Data 內；比較時以減法改寫 $\text{offset}+w\times h\le\text{size}$，避免加法溢位。
\end{itemize}
由於所有範圍都在載入時驗證過，繪製時可以直接取用 bitmap，不必每畫一個字都重複檢查邊界。

\subsection{查找與替代字元}

Glyph Table 已依 code point 排序，因此以 \lstinline|std::lower_bound| 進行二分搜尋，$N$ 個字形只需 $O(\log N)$ 次比較；載入時檢查嚴格遞增，正是為了保證二分搜尋的前提成立。找不到字元時依序改用 U+FFFD 與問號；若字型連這兩者都沒有，則不繪製 bitmap，只以 pixelSize 推進 pen，使後續文字仍維持在正確位置。字形的著色與繪製流程見第~\ref{sec:gfnt-render} 節。
