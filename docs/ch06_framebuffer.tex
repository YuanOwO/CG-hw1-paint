\section{Framebuffer 與輸出}
\label{sec:framebuffer}

\subsection{Color Buffer}

ColorBuffer 以 RGBA 格式儲存 framebuffer，每個 channel 使用 1 byte。擷取時，程式先把 UI 的左上角座標換成 OpenGL 的左下角座標，再從 single-buffer 的 front buffer 呼叫 \lstinline|glReadPixels()|。還原畫面前會暫時關閉 blending、depth、stencil、scissor 與 alpha test，接著用 \lstinline|glDrawPixels()| 寫回像素。函式結束前會還原 PACK/UNPACK alignment 與其他 OpenGL state，避免影響後續繪圖。

圖~\ref{fig:framebuffer-coordinate} 顯示同一個擷取區域在兩套座標中的位置。UI 以左上角為原點，但 \lstinline|glReadPixels()| 的位置必須從 framebuffer 左下角計算，因此程式使用視窗高度、區域上緣與區域高度求出 \lstinline|bottom|。讀回的 pixels 仍由下往上排列，座標轉換本身不會翻轉資料。

\subsection{Display Restore}

Window 會分別記錄「內容需要重畫」與「畫面需要重新擷取」兩種狀態。內容改變或 cache 尺寸不符時，display callback 先重畫整棵 Element tree；等畫面完成而且沒有新的修改後，timer 才把 framebuffer 存入 ColorBuffer。下一次若只是視窗重新曝光，就能直接還原像素，不必重新走一次所有 Renderer。狀態轉換如圖~\ref{fig:color-buffer-flow}。

\subsection{圖片輸出}

輸出圖片時，程式會建立一個與 Canvas 相同尺寸的 GraphicsRenderWindow，關閉 Grid，並重用平常的 Canvas Renderer 重新畫出 Scene。呼叫 \lstinline|glFinish()| 確認繪圖完成後，再讀取 framebuffer，依 PPM P6 格式由上到下寫出 RGB bytes，alpha channel 不輸出。這種做法不會把主視窗的狀態列一起存進圖片。PNG 與 JPEG 目前沒有實作。

由於 ColorBuffer 的第 0 列位於畫面下方，PpmExporter 會從 \lstinline|height - 1| 反向走訪到第 0 列。圖~\ref{fig:ppm-export-layout} 以小型 pixel matrix 表示這個轉換，也標出 P6 header 與忽略 alpha channel 的位置。
